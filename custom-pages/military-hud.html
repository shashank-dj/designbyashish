The briefCase study

The A350F made its first flight from Toulouse on 29 September 2026. Airbus is running a flight-test programme of around 400 hours, with certification and first customer deliveries planned for the second half of 2027. This concept asks what its crew and loadmaster would need on screen if the interface were designed around one shared grammar instead of a collection of system pages.

Two users share one aircraft. The pilot needs to read state fast and act without error. The loadmaster needs to see a numeric limit become a physical consequence. The same alert, the same confirmation and the same balance bar serve both. The simulated flight is Airbus's own benchmark sector, Hong Kong to Anchorage at full payload.

Other details that shaped the interface: six interchangeable touchscreen displays, a cabin altitude of 6,000 ft, cargo air flows segregated from the crew areas with cargo temperature control down to 4 °C, and a floor designed for flexible pallet loading and centre of gravity management.

The doorThe feature operators asked for.

Airbus describes the A350F's main deck cargo door as the largest in the industry: a 175 in (4,445 mm) cut-out with a 169.5 in (4,305 mm) clear opening, electrically operated and placed behind the wing so the main deck and lower deck can be loaded at the same time. It is sized so large jet engines can be loaded without disassembly.

The HMI gives it its own element. A door card shows the state in words and colour, lists the interlocks that must be met (on the ground, engines shut down) and asks for a hold to open. The same door appears highlighted in the plan view, the 3D cutaway and a true-scale cross-section, where it is drawn against a 125 in pallet.

PrinciplesEach one is visible in the demo above.

One alert grammar

A tier is always a colour, a shape and a word together. Flight, fuel and cargo raise alerts into the same stack, so a loadmaster's CG warning reads exactly like a pilot's fuel caution.

Show the margin, not only the value

The speed tape carries a coloured margin strip and a distance-to-limit chip. The CG envelope shows a caution band and the path from empty aircraft to the current load.

Slow down irreversible actions

Selecting descent, discharging an extinguishing agent and locking a manifest all use the same hold-to-confirm control. Reversible changes stay one tap.

Borrow from the best interfaces

Flight simulators like Microsoft Flight Simulator treat the cockpit tablet as a set of small apps, and keep checklists beside live state. Here, checklists live inside the alert that triggers them, and the six-screen layout lets a crew move a briefing from one screen to another in a single action.

Reuse components across systems

The balance bar measures fuel left to right and lane load left to right. The segmented arc shows thrust and the loading gauge. Learn one, read both.

Component libraryLive instances, not screenshots.

Alert tiers

Colour, shape and label always travel together, so no tier depends on colour alone.

Hold to confirm

1.2 seconds, cancelable by release. Works with pointer, touch and the space bar.

Rotary dial

Drag in a circle, scroll, or use arrow keys. Shift or Page keys move in tens.

Segmented arc

A white fill with amber and red zones, and a cyan tick for the commanded value.

Balance bar

Zero sits at the centre. Zones are drawn on the track so the limit is visible before it is reached.

Segmented switch and toggle

A sliding thumb shows which mode is live. The toggle always spells out its state.

Colour has a jobFollows the long-standing alerting hierarchy in cockpit certification rules (CS-25.1322): red for warnings, amber for cautions.

Speeds use standard-atmosphere maths (indicated airspeed to Mach, true airspeed and ground speed); the overspeed and stall limits on the tape are simulated. The layout draws on the ideas behind ARINC 661 but is not an implementation of it.
